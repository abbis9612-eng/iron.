# Iron Horizon — دليل بدء البناء

Nov 17, 2026 · @DCC

## 1. ما تبقّى قبل البناء

التصميم مكتمل (وثيقة v3). الباقي خمس أشياء عملية، ولا واحدة منها تمنع البدء بالمرحلة 0 اليوم ما عدا الحسابات.

- [ ] **الحسابات:** حساب Unity (الخطة Personal مجانية)، حساب GitHub، اشتراك Claude يشمل Claude Code، وحساب Epic لمتجر Fab. مطلوب للمرحلة 0.
- [ ] **الرامات:** شريحة DDR5 ثانية 16GB بنفس السرعة (المجموع 32GB قناة مزدوجة). مطلوب قبل المرحلة 0.5.
- [ ] **الخرائط (محسومة):** ممر فولدا من بيانات Hessen DGM1 (1 م)، وصحراء مفتوحة من Copernicus GLO-30، بأرض حقيقية وبلدات خيالية. الوكيل يجهّز البيانات، وأنت تختار مربّع 1×1 كم من فولدا للمرحلة 0.5.
- [ ] **أصول المرحلة 0.5:** دبابة واحدة عالية الجودة، وحزمة Megascans للأرض والنبات، ومصادر أصوات (القسم 7).
- [ ] **Blender:** مجاني، يستخدمه الوكيل عبر سكربتات لتنظيف المجسمات. مطلوب قبل المرحلة 0.5.
- [ ] **مراجع بشري وجهاز ثانٍ:** مبرمج C# بالقطعة يراجع مجلد Core/Sim بعد المرحلة 0، وجهاز بمعالج AMD (جهاز صديق يكفي) لاختبار الحتمية. مطلوب لبوابة المرحلة 0.

مؤجّل ولا يوقف شيئاً: المراجعة القانونية لأسماء المعدات الحقيقية قبل أي نشر عام.

## 2. الأدوار

أنت المخرج وصاحب القرار، وClaude Code المهندس المنفّذ، وهذه المحادثة غرفة التخطيط والمراجعة. الوثيقة v3 هي القانون: أي تغيير يُكتب فيها أولاً ثم يُنفّذ.

| الدور | من | المسؤولية |
| --- | --- | --- |
| المخرج والمنتج | أنت | تقرر الاتجاه، توافق على البوابات، تجرّب اللعب، تحكم على «الواو»، وتعدّل التوازن من جداول Excel |
| المهندس المنفّذ | Claude Code على جهازك | يكتب الكود، يشغّل الاختبارات، يصلح، يوثّق، ويعمل commit |
| المستشار والمراجع | Claude في هذه المحادثة | يكتب نص المهام، يراجع النتائج والقرارات، يبحث عن الجديد، ويحدّث الوثيقة |
| الفنّ | أصول مشتراة + سكربتات Blender + فنان بالقطعة عند الحاجة | المجسمات والنسيج والصوت |

قاعدة ذهبية: مهمة واحدة صغيرة في كل مرة، لها معيار قبول تقدر تشوفه بعينك أو بنتيجة اختبار.

## 3. تجهيز الجهاز (مرة واحدة، ساعة تقريباً)

كل الأوامر تُنسخ في PowerShell عادي (64-bit) بدون صلاحيات مدير. بعد كل تنصيب افتح نافذة PowerShell جديدة حتى يتعرّف على الأمر.

1. **Git for Windows** من موقع git-scm.com (موصى به مع Claude Code على ويندوز). بعده:

```powershell
git --version
git lfs install
git config --global user.name "DCC"
git config --global user.email "<بريدك الذي في GitHub>"
```

2. **Unity Hub** من موقع Unity، سجّل دخولك، ثم ثبّت آخر نسخة من **Unity 6.6** (فرع 6000.6). لا تحتاج وحدات إضافية الآن.
3. **Claude Code**، ثم تحقق وسجّل دخولك:

```powershell
irm https://claude.ai/install.ps1 | iex
claude --version
claude doctor
```

4. **Unity CLI** (نسخة تجريبية مجانية تخلّي الوكيل يشغّل Unity ويختبرها):

```powershell
$env:UNITY_CLI_CHANNEL='beta'; irm https://public-cdn.cloud.unity3d.com/hub/prod/cli/install.ps1 | iex
unity --version
unity auth login
```

5. **Blender** (مجاني) من blender.org، قبل المرحلة 0.5 فقط.

إذا قال PowerShell إن الأمر غير معروف: أغلق النافذة وافتح واحدة جديدة. إذا استمر، اسأل Claude Code نفسه أو ارجع هنا بالرسالة الكاملة.

## 4. اليوم الأول: إنشاء المشروع وربط Claude Code

الهدف: مشروع Unity فارغ مربوط بـ GitHub، وClaude Code يقدر يشغّل المحرر ويقرأ الوثيقة.

1. اصنع مستودعاً **خاصاً** فارغاً على GitHub باسم iron-horizon (بدون README).
2. من Unity Hub: مشروع جديد ← Unity 6.6 ← قالب **Universal 3D**. المسار قصير بحروف إنجليزية وبدون فراغات، مثل D:\\Games\\IronHorizon.
3. اترك المحرر مفتوحاً، وافتح PowerShell في مجلد المشروع:

```powershell
cd D:\Games\IronHorizon
unity pipeline install
```

بعدها تظهر قائمة Pipeline داخل المحرر.

4. شغّل Claude Code بنفس المجلد بالأمر claude، ثم داخله ثبّت إضافة Unity الرسمية:

```text
/plugin marketplace add Unity-Technologies/unity-agent-plugin
/plugin install unity@unity-agent-plugin
```

للتحقق اكتب /unity: ولازم تظهر قائمة مهارات Unity.

5. من قائمة وثيقة v3 نزّلها بصيغة Markdown، واحفظها داخل المشروع باسم Docs\\GDD.md.
6. ابدأ بالمهمة T1 من القسم 6. هي تصنع CLAUDE.md وتربط GitHub بنفسها.

## 6. مهام المرحلة 0 (جاهزة للنسخ)

ثماني مهام بالترتيب، كل واحدة بجلسة. نهايتها = بوابة المرحلة 0: المشروع يُبنى، الاختبارات خضراء، الإعادة تعطي نفس البصمة على جهازين، والمراجع البشري وافق على النواة. لا توجد أي رسوم في هذه المرحلة، وهذا طبيعي: هي أساسات البيت.

- [ ] **T1 · المستودع وCLAUDE.md**

```text

المرجع: Docs/GDD.md القسم 0

- .gitignore رسمي لـ Unity، و.gitattributes يرسل fbx وpng وpsd وtga وexr وwav وogg وblend إلى Git LFS.
- اربط المستودع بـ <رابط مستودع GitHub> وارفع أول commit.
معيار القبول: المستودع على GitHub بدون Library/ وTemp/، وgit lfs ls-files يعمل.
```

## 7. المرحلة 0.5: الأصول والاختبار البصري

هنا تتقرر «الواو». نشتري أقل شيء ممكن، ونثبت المستوى البصري قبل شراء أي شيء آخر.

**الدبابة الأولى (T-72A مقترحة):** قبل الشراء أرسل لي الرابط وأراجعه. الشروط:

- [ ] البرج والمدفع قطع منفصلة (أو سهلة الفصل).
- [ ] نسيج PBR بدقة 2K أو أعلى.
- [ ] المثلثات بحدود 60 ألف أو معها LODs.
- [ ] الرخصة تسمح بالاستخدام التجاري في Unity.
- [ ] صور قريبة تظهر التفاصيل بوضوح.

**الأرض:** حزمة Megascans من Fab (تربة، صخور، عشب، شجيرات) تشبه طبيعة المنطقة المختارة، وقطعة ارتفاعات 1×1 كم من Copernicus GLO-30 يحوّلها الوكيل إلى تضاريس Unity.

**الصوت:** انفجار ومدفع دبابة ومحرك بثلاث طبقات مسافة، من ElevenLabs SFX v3 (خطة مدفوعة للتجاري) أو مكتبات CC0.

مهام الوكيل بالترتيب (بنفس قالب القسم 5):

1. **V1 الأرض:** مربّع 1×1 كم من فولدا ببيانات DGM1 (أرض مجرّدة فلا تحتاج تنعيماً)، نسيج Megascans، نباتات، قرية خيالية صغيرة بمعمار ألماني، وإضاءة APV مخبوزة.
2. **V2 الدبابة:** خط الإنتاج من ملف الاتجاه الفني (القسم 7): تنظيف بسكربت Blender، المقابس، LODs، حالات الضرر، الصندوقان الموجّهان، وبوابة الاستيراد.
3. **V3 الانفجار:** الطبقات الأربع + حفرة + اهتزاز + صوت (GDD القسم 10).
4. **V4 اللقطة:** مشهد عرض فيه الدبابة ترمي والانفجار يضرب الأرض، بإعداد «متوسط» وSTP، مع عدّاد إطارات ظاهر، والقياسات الحقيقية في Docs/Perf.md.
5. **V5 تجربة جانبية:** فصل البرج آلياً بـ Hunyuan3D-Part على مجسم واحد، للتقييم فقط ولا يدخل اللعبة بسبب الرخصة.

البوابة: أنت تشوف المشهد على لابتوبك، ونراجع اللقطة هنا سوية. إذا ما طلع «واو»، نعدّل الأصول أو الإضاءة قبل المرحلة 1.

## 8. كيف تختبر وتبلّغ بدون كود

دورك تشوف وتحكم، مو تقرأ كود. كل مهمة ينتهي ملخصها بـ «كيف أجرّبه»، وأنت تتبعه خطوة بخطوة.

1. افتح المشهد المذكور في الملخص، واضغط Play.
2. راجع كل بند من معيار القبول بعينك.
3. نجح؟ أشّر المهمة هنا وفي وثيقة v3. فشل؟ اكتب بلاغاً بالقالب التالي.

```text
بلاغ خلل — المهمة <الرمز>
ماذا فعلت: <الخطوات بالترتيب>
ماذا توقعت: <النتيجة المطلوبة>
ماذا حدث: <النتيجة الفعلية>
الأدلة: لقطة شاشة أو فيديو، ملف الإعادة إن وُجد، ونص الخطأ من Console
المطلوب: أعد إنتاج الخلل أولاً، واكتب اختباراً يفشل بسببه، ثم أصلح.
```

**أدوات الأدلة المدمجة في ويندوز:** Win+Shift+S للقطة، وWin+Alt+R لتسجيل فيديو عبر Xbox Game Bar. نص الخطأ تنسخه من نافذة Console داخل Unity. ابتداءً من المرحلة 1 كل معركة تُحفظ كملف إعادة، وهذا أقوى دليل.

**قاعدة الثلاث محاولات:** إذا فشل الإصلاح ثلاث مرات، توقف. اطلب من الوكيل إرجاع آخر نسخة سليمة من Git، وتعال هنا بالبلاغ والملخص حتى نشخّص المشكلة من زاوية ثانية.

**عند كل بوابة مرحلة:** ابعث هنا ملخص الوكيل + لقطات أو فيديو، ونراجع معاً قبل الانتقال.
